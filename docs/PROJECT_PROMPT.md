## 主 Prompt

你正在参与开发一个名为“**OOTD 立体日记**”的应用。请先完整阅读 `docs/PROJECT_REQUIREMENTS.md`，并把它作为当前阶段产品范围和验收标准的主要依据。随后检查仓库现状、已有文档、代码、配置和测试，再处理我本次提出的任务。

### 产品背景

这是一款以喜欢记录每日穿搭的女性用户为主要目标人群的轻量应用。它的核心不是数字衣橱、虚拟试衣或社交社区，而是把每日穿搭照片转化为具有收藏感和分享价值的立体 OOTD 形象。

产品的一句话定义是：

> 每天拍一张，把今天的穿搭变成立体 OOTD，并自动收藏和分享。

### 当前唯一核心闭环

```text
拍照 / 相册上传
        ↓
生成今日 OOTD 立体形象
        ↓
记录到日期 / 分享
```

### MVP 必须保持的范围

MVP 聚焦以下能力：

- 拍摄全身照或从相册选择；
- 检查照片是否适合生成，并给出可理解的修正提示；
- 创建异步生成任务，展示进度，支持离开页面后恢复；
- 生成具有统一审美的今日 OOTD 立体形象；
- 输出可实时渲染的立体资产，支持用户通过手势在允许范围内主动转动查看；
- 生成成功后自动按用户当地日期保存；
- 通过日历和时间线回顾记录；
- 预览并导出静态分享卡片；
- 支持重新生成、删除、隐私控制和失败重试。

### 当前明确不做

除非我在具体任务中明确变更范围，否则不要主动加入：

- 首次进入时创建个人数字人；
- 正面/侧面/背面建模流程；
- 数字衣橱；
- 单件衣服录入；
- 电商链接导入；
- 自定义搭配或换装；
- 尺码和合身判断；
- 实时 AR 试衣；
- 社区、关注、点赞和评论；
- 身材或穿搭评分。

### 关于“立体”的关键约束

- “立体”首先是用户体验目标，不预先锁定技术实现；
- 当前 AI 范围是对用户照片进行检测、分割、深度/法线估计、人体与服装重建、纹理处理和模型优化，不包含生成式生图或生视频；
- 单张照片无法准确恢复背面和遮挡区域，不得宣传为精确 360° 数字孪生；
- 可以评估 2.5D 几何、参数化人体拟合、单图穿衣人体重建或混合建模方案；
- MVP 更重视结果好看、本人有辨识度、服装特征清晰、风格统一和分享效果；
- 结果页的立体感必须来自用户可操作的实时模型或等价可交互资产，不能用自动旋转视频替代；
- 必须为无法加载复杂资产的情况提供静态预览保底；
- 技术选型应同时评估质量、耗时、单次成本、失败率和移动端性能。

### 已确认的本地实验硬件

- 本地 AI/建模 PoC 使用单张 NVIDIA RTX 3090（24GB 显存）；
- 当前阶段以预训练模型推理和建模链路验证为主，不以训练大型模型为目标；
- 技术方案应能在上述单卡环境中完成图片处理、人体/服装建模、纹理与模型资产导出；
- 系统内存、存储、操作系统和 CUDA/PyTorch 版本在确定具体软件路线后锁定。

### 已确认的当前开发形态

- 当前优先实现本地桌面原型，不先开发移动端或跨平台应用；
- 桌面原型采用本地 Web 界面加 Python 建模服务：React/TypeScript/Three.js 负责界面和实时模型查看，FastAPI/PyTorch 负责图片处理、任务管理和人体/服装建模；
- 第一阶段使用 SQLite 和本地文件系统，不引入完整云后端、账户、Redis、对象存储或推送通知；
- 浏览器原型验证成功后，如需要安装包再评估 Tauri；
- 详细方案见 `docs/DESKTOP_PROTOTYPE_TECH_STACK.md`。

### 产品与体验原则

1. 用户应先看到价值，再被要求补充资料或注册。
2. 不要求用户填写身高、三围或逐件服装信息。
3. 拍照到结果的路径尽可能短，结果页是体验重点。
4. 原图和生成记录默认私密，分享前必须预览。
5. 不对用户身体进行评分或价值判断，不擅自用产品文案强化胖瘦焦虑。
6. 对 AI 推测、生成失败和结果差异保持诚实。
7. 网络中断、App 退出和重复点击不能造成任务或记录丢失。
8. 不为了展示技术而增加与核心闭环无关的功能。

### 工程工作方式

处理后续任务时，请遵循以下方式：

1. 先检查仓库现状，不假设某个技术栈已经存在。
2. 如果仓库包含 `AGENTS.md` 或更具体的项目说明，先读取并遵守。
3. 修改前说明本次任务会影响的范围；实现后运行与风险相称的检查或测试。
4. 保持改动聚焦，不顺手扩张产品范围或大规模重构无关代码。
5. 对会显著改变成本、隐私、数据结构或核心体验的决定，明确列出假设和取舍。
6. 需要技术选型时，优先给出基于本项目目标的推荐方案，不只罗列工具名称。
7. 设计异步生成流程时，必须覆盖任务幂等、状态恢复、失败重试、重复提交和资产清理。
8. 设计数据层时，至少考虑用户、OOTD 记录、媒体资产、生成任务和生成结果。
9. 设计隐私时，至少考虑原图默认私密、授权访问、第三方 AI 数据政策、删除流程和日志脱敏。
10. 若需求与 `docs/PROJECT_REQUIREMENTS.md` 冲突，以我当前会话中的明确指令为准，并同步更新文档。
